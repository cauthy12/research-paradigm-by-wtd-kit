# 研究工作区约定（research paradigm · by WTD）

本工作区是一个"一人研究公司"：接需求 → 先查本地 → 出判断 → 留痕 → 交付。
这里写的是**默认值**；用户当轮说的话永远优先。

## 1. 硬边界（违反即停，不自行改道）

- 禁区目录只读（见 `.research/config.yml` 的 `forbidden_roots`）。被沙箱拦下 = 权限阻断：停下报告，不换路径硬写。
- 知识库/经验库正文**只追加不覆盖**；要推翻旧结论，加一行墓碑（`superseded_by: … @日期 — 一句原因`），不删旧文。
- 密钥只从环境变量读；文件、日志、回复里不出现明文。
- 额度型 API（见 `metered_apis`）未经用户当轮要求不真调；真调前后必须记账（预算 → 调用 → 记账）。
- 拿不到就报"拿不到"：不猜、不编、不伪造数据。

## 2. 每个任务的三条留痕

- **开始**：向 `runs/<任务名>.md` 追加"开始"行。写失败即终止，并说明"日志通道故障"。
- **进度**：每完成一个单元追加一行。
- **结束**：追加"结束"行，含 `digest:` 一句话结论，以及外部源对账（源端条数/时间戳 vs 本地落盘数，缺额写明）。
- 单轮问答、轻量解释、一次性小改不做。

## 3. 默认顺序：先本地，后外部

1. 先在工作区、知识库、已有留痕里检索（流程见 `.research/rules/10-retrieval.md`）。
2. 命中蒸馏层（已有人类验证的结论）优先采信，先看成文日期是否过期。
3. 再读原文精读；最后才用外部检索/付费 API。
4. 产出里标注来源分层：蒸馏层 / 梗概层 / 原文 / 外部。

## 4. 分片索引（不在常驻上下文里，按需读）

| 场景 | 读哪片 |
|---|---|
| 判断旧结论还能不能用、要不要打墓碑、优先级冲突 | `.research/rules/00-core.md` |
| 检索顺序、新鲜度门槛、额度记账 | `.research/rules/10-retrieval.md` |
| 留痕格式、digest、对账、INDEX 生成 | `.research/rules/20-logging.md` |
| 卡住/要停/重试/归层/三件套/ADR | `.research/rules/30-failure.md` |
| 读 PDF/Word/图片、交付前校验、落位命名 | `.research/rules/40-delivery.md` |
| 改规则本身、多平台差异、定时任务归属 | `.research/rules/50-governance.md` |

## 5. 交付与落位

- 交付物进 `output/`（或 config 的 `deliverables_dir`），不放仓库根。
- 结构性交付（表、清单、可核对数字）优于叙述性长文；默认不做图表/可视化，用户点名才做。
- 交付前过一遍 `.research/rules/40-delivery.md` 的机械校验清单。

## 6. 优先级阶梯

用户当轮指令 > 本文件与 `.research/rules/` 的硬边界 > 其余条款 > 蒸馏层结论 > 梗概层 > 原文 > 历史留痕摘要。
冲突时高者胜，并在回复里说明"哪里冲突、按哪条走"。

## 7. 技能（任务命中时先加载，别凭记忆复述流程）

`rp-brief`（开题定边界）· `rp-retrieval`（检索执行）· `rp-run-log`（留痕）· `rp-handoff`（会话交接）· `rp-deliverable-check`（交付前校验）。
