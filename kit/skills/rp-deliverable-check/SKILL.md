# rp-deliverable-check · 交付前校验

机器能查的别靠眼睛；眼睛该看的只有"这答案对不对"。

## 1. 机械校验（六项，逐项打勾）

- [ ] **能打开**：用对应库重新读一遍文件（python-docx / openpyxl / python-pptx / pdfplumber），不报错。
- [ ] **无假数据**：搜 `Lorem`、`示例`、`TODO`、`XXX`、`#REF!`、`NaN`、`0.00%` 等占位残留。
- [ ] **结构完整**：表格行列数对得上源数据；没有合并单元格吞数据；图表引用的数据区没空。
- [ ] **数字一致**：抽 3 处关键数字，与正文/源表交叉核对（合计、增速、占比）。
- [ ] **干净**：水印、批注、修订痕迹、隐藏工作表清掉。
- [ ] **命名落位**：`<主题>_<YYYYMMDD>.<ext>`，落在输出目录，不在仓库根或临时目录。

能自动化的用脚本跑（`check.mjs` 只管工作区结构，交付物校验要单独跑），跑完把结果写进结束行。

## 2. 内容校验（三项）

- [ ] 每条结论有来源与日期；来源分层标注了（原文/蒸馏层/外部）。
- [ ] 关键数字带口径（单位、时点、含税与否）。
- [ ] 反面情形/局限性写了（至少一条"这个结论可能错在哪"）。

## 3. 交付话术

顺序固定：

1. **结论**（一句，带数字）
2. **证据**（3 条以内，按强度排序）
3. **局限**（没验证什么、哪些是推测、什么情况下结论会翻）
4. **下一步**（建议动作或需要拍板的事项）

## 4. 常见坑

| 坑 | 后果 | 预防 |
|---|---|---|
| 用模板改了数据但没查残留 | 交付件里带着别人的公司名 | 交付前全文搜一遍旧主体名 |
| Excel 公式没重算 | 打开显示 `#VALUE!` | 用 openpyxl 重算或写成值 |
| 图表数据区断链 | 图是空的 | 打开后逐图确认 |
| 长文档目录页码不对 | 显得不专业 | 生成后重刷目录域 |
| 文件名带"最终版" | 版本混乱 | 只用日期 |

## 5. 反模式

- "看起来没问题"就交——打开都不打开。
- 只查内容不查文件——文件损坏比结论错更尴尬。
- 交付时不写局限——把不确定性藏起来，后面一定反噬。
