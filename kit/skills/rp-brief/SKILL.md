# rp-brief · 开题

目标：**在动手之前**把"做完"定义清楚。开题只要 10 分钟，省的是后面两天的返工。

## 1. 先问三个问题（能答就不问用户，答不了才问）

1. **决策是什么**：这份研究要支撑谁做哪个决定？（"要不要投"和"了解一下"是两份完全不同的活）
2. **边界在哪**：时间范围、地域、公司集合、技术路线，各圈到什么程度。
3. **判据是什么**：什么数字/事实出现时，结论会从"行"翻成"不行"。

用户没答的就**写假设**，不要留空。假设要显式列出来，方便后面被推翻。

## 2. 输出一份任务书（写进 `tasks/<任务名>/AGENT.md`）

```markdown
# <任务名>

## 目标
一句话：回答什么问题、支撑什么决策。

## 边界
- 时间：…
- 范围：…
- 明确不做：…

## 判据（什么算结论成立）
- 关键指标 / 阈值 / 反面条件

## 交付形态
- 给谁看、多长、要不要表、落哪个目录

## 验收标准
- [ ] 每条结论都有来源分层标注
- [ ] 关键数字有口径
- [ ] 反面情形写了
```

## 3. 任务分型（决定走哪条路）

| 类型 | 走法 |
|---|---|
| 产业深度研究 | 框架 → 分角度并行 → 证据 → 反证 → 收敛 |
| 单企业尽调 | 主体 → 业务 → 财务 → 治理风险 → 估值区间 → 反面 |
| 利润预测/估值 | 分板块建模 → 三档情景 → 假设来源 |
| 通用市场/文献 | 检索 → 归类 → 对比表 → 判断 |
| 单点事实核查 | 检索 → 出处 → 一句话结论 |

## 4. 反面情形先写

开题时就写"如果结论是反的，最可能因为什么"。这份清单后面会变成你的反证任务，也是最容易出彩的部分。

## 5. 反模式

- 目标写成"全面了解 X"——不可验收。
- 边界写"尽量全"——等于没边界。
- 判据留空——最后只能凭感觉下结论。
- 直接开写长文——写完才发现答的不是那个问题。
