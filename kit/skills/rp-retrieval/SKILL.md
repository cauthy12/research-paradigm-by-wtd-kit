# rp-retrieval · 检索执行

## 1. 四层顺序，不跳层

```
① 本地内容级检索      kb_search / grep 索引：知识库全文 + 梗概库 + 订阅索引
② 蒸馏层直读          有人类验证过的结论（专题/主线库）——先看成文日期
③ 原文精读            按梗概里的页码/行号读原文，取证据级事实
④ 外部 / 付费 API     只用前三层没覆盖的部分，且记账
```

每层的产出都要标：`蒸馏层` / `梗概层` / `原文` / `外部`。**不要写成一段话把不同强度证据混在一起。**

## 2. 检索动作清单

- 先想关键词的三种写法：术语、同义词、英文/缩写（CJK 检索尤其需要）。
- 一次检索拿不到就换**检索面**（换索引、换库、换实体名），不要重复同一条 query 三遍。
- 命中后立刻记录：文件路径 + 行号/页码 + 日期，否则后面引用会丢。
- 关键数字至少两个来源，或一个来源 + 一次内部一致性校验（合计、增速、单位）。

## 3. 新鲜度

- 蒸馏层超 `freshness.distilled_layer_max_age_months`（默认 6 个月）→ 先用原文核一遍再采信。
- 蒸馏层与原文冲突 → 以原文为准，并给蒸馏层加墓碑行（`superseded_by: … @日期 — 原因`）。
- "最新"必须带时间戳。

## 4. 未命中与降级

- 未命中要写清：查了什么、查了哪几层、为什么没命中（没有 / 有但拿不到 / 有但过期）。
- 走零额度替代（公开搜索、公开数据）时标 `DEGRADED` + 未验证范围。
- 外部源必须对账：源端条数/时间戳 vs 本地落盘数，差额写明。

## 5. 额度型 API（见配置 `metered_apis`）

1. 未经用户当轮要求不真调。
2. 调前查预算余量。
3. 成功即记账（一次一条）：API、单位、任务、用途。
4. 记错用负数冲正，不删行。
5. 收尾出报表，路径写进结束行。

## 6. 检索产出格式

```markdown
- 结论：<一句话>
  - 来源：<路径或链接>（分层：原文 / 蒸馏层 / 外部）
  - 日期：YYYY-MM-DD
  - 口径：<单位、时点、口径>
```

## 7. 反模式

- 每层都查一遍却都不精读——最贵的查法是"浅查四遍"。
- 直接拿搜索结果当结论，不读原文。
- 只用一次检索就宣布"没有资料"。
- 把外部数据当内部数据用，不标来源。
