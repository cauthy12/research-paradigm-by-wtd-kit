# rp-run-log · 留痕

留痕不是为了好看，是为了**下次能接上**和**出事能复盘**。

## 1. 文件

`${runs_dir}/<任务名>.md`，一个任务一个文件，续写同一份。只追加，不改写历史行。

```markdown
# <任务名>

| 时间 | 状态 | 说明 |
|---|---|---|
| 2026-01-01 09:00 | 开始 | 目标：…；边界：… |
```

## 2. 五行

| 行 | 何时 | 写什么 |
|---|---|---|
| 开始 | **第一动作**，干任何活之前 | 目标、边界、预计步数 |
| 进度 | 每完成一个单元 | 完成了什么、产出路径、下一步 |
| 结束 | 收尾 | 结论 + 产出路径 + 没做完的 |
| 对账 | 有外部源时 | 源端条数/时间戳 vs 落盘数、差额 |
| digest | 最后一行 | 一句话结论 + 一个可核对数字 |

**开始行写不进去 → 立刻终止**，报告"日志通道故障"。不要先干活后补日志（补记要写明"补记"，不伪造时间）。

## 3. digest 的写法

```markdown
| 2026-01-01 11:20 | digest | 结论：X 大概率成立（3 条独立证据）；关键数字：本地落盘 128/128 条，无差额 |
```

句式：**结论 + 支撑强度 + 一个数字**。给未来的自己 grep 用。

## 4. 对账（外部源任务必做）

- 源端条目数 / 时间戳 / 本地落盘数，三个数都写。
- 不一致：写差额与原因（分页漏了？接口截断？去重了？）。
- 无法核实：标 `DEGRADED` + 未验证范围，并登记恢复条件。

## 5. 索引

跑 `check.mjs --write-index` 重建 `runs/INDEX.md`（文件/更新时间/行数/最新状态/摘要）。索引是脚本产物，不手写、不塞进上下文。

## 6. 自检

`node check.mjs` 会检查：最近 10 份有无表头、有无结束行、有无 digest。报 warn 就补。

## 7. 反模式

- 一天下来只有"我做了很多事"的对话记录，没有可复查的文件。
- 结束行写"已处理"——三个月后看不懂处理了什么。
- 失败不写进日志（静默结束）——等于把问题留给自己。
