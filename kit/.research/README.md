# .research/ — 规则分片怎么用

`AGENTS.md` 是常驻层（每次会话自动读到）；这个目录是**按需层**，只有用到才读，读完不必复述。

## 读取纪律（渐进披露）

1. 先看 `AGENTS.md` 第 4 节的分片索引，判断当前动作命中哪片。
2. 只读命中那一片，不要一次性把 6 片全读进来（前缀缓存和注意力都要省）。
3. 分片里出现矛盾时，按 `AGENTS.md` 第 6 节优先级阶梯裁决，并在回复里说明按哪条走。

## 写纪律

- 分片是规则的**派生副本**：唯一权威源在 `config.yml` 的 `rules_source`（如 `D:\workspace\rules\constitution.md`）。
- 要改规则：改源 → 重新生成/同步 → 再更新这里的分片。直接改分片会被下次同步覆盖（先例：只改了一个平台副本，三份载体漂移）。
- 新增条款：先问"不知道这条会不会立刻做错且代价高"。会 → 进 `00-core.md` 与 `AGENTS.md`；不会 → 进对应分片。

## 分片职责

| 文件 | 职责 | 常驻？ |
|---|---|---|
| `00-core.md` | 硬边界、价值判定与墓碑、优先级、缓存与预算纪律 | 是（摘要进 AGENTS.md） |
| `10-retrieval.md` | 分层检索、本地优先、新鲜度、额度记账 | 否 |
| `20-logging.md` | 留痕三行、digest、外部源对账、INDEX | 否 |
| `30-failure.md` | 停、重试、归层、三件套、ADR、DEGRADED 债务 | 否 |
| `40-delivery.md` | 文件处理路由、交付校验、不做自动可视化 | 否 |
| `50-governance.md` | 规则单源与生成、平台差异、定时任务归属 | 否 |
