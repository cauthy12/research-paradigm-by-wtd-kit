# 10-retrieval · 分层检索、本地优先、额度、新鲜度

> 任何"找资料/查历史/调外部数据"的动作前读这一片。

## 1. 分层检索顺序（不跳层）

```
① 本地内容级检索（kb_search 或等价脚本，覆盖知识库 + 梗概库 + 订阅索引）
② 命中主题有蒸馏层 → 直读蒸馏层（技术专题/主线库），人类验证过，优先采信
③ 按 deep_pages/行号精读原文（证据级）
④ 仍不全 → 外部检索或付费 API
```

产出必须标注来源分层：**蒸馏层 / 梗概层 / 原文 / 外部**。混着写等于把证据强度抹平。

## 2. 为什么本地优先

- 已付费订阅的历史文档、已建的梗概库，重复调用外部 API 是纯浪费（还计费）。
- 梗概库带实体与深读页码，能直接跳到原文段落，比重新检索快。
- 未命中再调外部 API，并且调完把新资料**回填**进本地（下次就不用再调）。

## 3. 新鲜度门槛

- 命中蒸馏层先看**成文日期**：超过 `freshness.distilled_layer_max_age_months`（默认 6 个月）的，先核对最新原文/研报再用。
- 蒸馏层与最新原文冲突时：以原文为准，并给蒸馏层打墓碑。
- 检索结果里的"最新"必须有时间戳，不能只写"近期"。

## 4. 额度型 API 纪律

见 `metered_apis`（谁归属、预算文件在哪）。

1. 未经用户**当轮**明确要求不真调；开题批准过的不必再问。
2. 调用前查预算余量。
3. 调用成功后**一次一记**：API 名、消耗单位、任务名、一句话用途（不写密钥）。
4. 记错用负数冲正，**不删行**。
5. 相关任务收尾时出月度报表，并把报表路径写进结束行。
6. 不可用时走零额度替代，并在回复与留痕里标 `DEGRADED` + 未验证范围。

## 5. 深度研究 / 尽调 / 估值：走流水线，不走自由发挥

- **产业深度研究**：立分析框架 → 分工（多角度并行）→ 收集证据 → 反证（专门找反例）→ 收敛判断 → 标注不确定性。不要一上来就写综述。
- **单企业尽调**：主体 → 业务与收入结构 → 财务质量 → 治理与风险 → 估值区间 → 反面情形。
- **利润预测/估值**：分业务板块建模，给三档情景（悲观/中性/乐观），每个假设写来源。

自有领域（`domains`）一律先查知识库再走外部；这是省额度也是保精度。
