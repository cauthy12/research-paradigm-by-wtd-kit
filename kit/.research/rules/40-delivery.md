# 40-delivery · 读文件、做交付、落位

## 1. 读文件先路由

读 PDF / Word / PPT / 图片 / 音频、OCR、整理成文档之前，先**判断类型再选工具**，不要一把梭：

| 输入 | 默认路线 |
|---|---|
| 纯文本 PDF | 文本层提取（pdfplumber/pdftotext），先判有没有文字层 |
| 图片型 PDF | 先按页渲染成图，再走本地 OCR，最后人工校对关键数字 |
| Word/PPT/Excel | 结构化解析（docx/pptx/openpyxl），保留表格 |
| 图片 | 本地 OCR 为主；只有图表语义（趋势、对比）才用多模态 |
| 音频/会议 | 转录 → 按发言人切分 → 与手记核对 |

OCR 取舍顺序：**准确率 > 速度 > 成本**；默认本地零 API 管线，批量文字转录不用远程多模态。

## 2. 交付物形态

- 结构性交付优于叙述性长文：表、清单、可核对数字、"下一步该做什么"。
- **默认不做图表/示意图/看板**；用户点名要图才做。
- 一页能说清就一页；长文必须有目录与结论前置。
- 交付物落在 `${deliverables_dir}`（或工作区 `output/`），**不放仓库根、不放临时目录**。

## 3. 交付前机械校验（必做）

对 PPT / Excel / Word：

- [ ] 文件能打开、不损坏（能被对应库重新读一遍）
- [ ] 没有模板残留的假数据/占位文字（"Lorem"、"示例"、`#REF!`）
- [ ] 表格没有被截断、合并单元格没有吞掉数据
- [ ] 数字与正文一致（抽样 3 处交叉核对）
- [ ] 水印/批注/修订痕迹清掉
- [ ] 文件名符合约定（主题 + 日期，不含"最终版""修改后"这类词）

## 4. 落位与命名

- 交付物一律进输出目录；工作中间产物留在任务目录，不污染输出区。
- 文件名：`<主题>_<YYYYMMDD>.<ext>`；同一主题多版本用日期区分，不用 v2-final-final。
- 只读区（禁区）不能直接落位时：降级暂存 + 在回复和留痕里写明"待用户 Copy-Item 落位"，**不得静默改道到别的目录**。

## 5. 交付时说什么

- 先说结论，再说证据，最后说局限（哪里没验证、哪些是推测）。
- 数字给口径（时点、单位、含不含税）。
- 引用外部来源给链接；引用本地资料给路径 + 行号。
