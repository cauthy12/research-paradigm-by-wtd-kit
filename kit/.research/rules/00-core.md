# 00-core · 硬边界、价值判定、优先级、缓存纪律

> 常驻层的完整版。`AGENTS.md` 只放摘要；判断拿不准、或要推翻旧结论时读这一片。

## 1. 五条硬边界

1. **禁区只读**：`forbidden_roots` 里的路径只读。唯一例外见 `write_exceptions`（纪要落位）。
   被沙箱/权限拦下 = 权限阻断，**停下报告**；降级暂存到 `staging` 并写明"待用户 Copy-Item 落位"。不得硬写、不得静默改道。
2. **只追加不覆盖**：知识库正文、经验库、runs 只追加。要推翻旧结论 → 加墓碑行，原文保留。
3. **技能唯一权威源**：技能改在 `skills_source`，平台副本只读同步。修订以"落进源库 + 同步副本 + 留痕"为完成标志。禁止在平台副本上直接迭代（先例：只落了一个平台，三副本漂移）。
4. **密钥只走环境变量**：文件、日志、回复、提交历史里不出现明文；缺 key 直接报缺，不猜不生成。
5. **不编数据**：拿不到就是拿不到。来源分层标注（蒸馏层/梗概层/原文/外部）不得混用。

## 2. 上下文价值判定（什么时候一条信息"作废"）

判据是**是否仍然为真、是否仍然有用**，不是长度、不是时间先后。

四类作废信号：

| 信号 | 判定 |
|---|---|
| 被取代 | 同一对象后来有了新结论/新版本/新数据（`superseded-by-*`） |
| 被推翻 | 后续证据与它矛盾，且新证据更强 |
| 重复 | 同内容第二次出现，或只是换了措辞 |
| 已消化 | 已沉淀成规则/结论，原文只在需要溯源时才读 |

处置一律是**墓碑而不是删除**：

```
superseded_by: <新条目/新版本> @<YYYY-MM-DD> — <一句原因>
```

- 打了墓碑的条目，默认不再被检索层采信（除溯源）。
- 未打墓碑的旧条目，**不得**在检索中被当成已经过期的内容忽略——那属于无记录淘汰。
- 墓碑行本身要能被机器读：键名固定、日期 ISO、原因单行。

## 3. 优先级阶梯（冲突时从高到低）

1. 用户当轮明确指令
2. 硬边界（本片第 1 节）
3. 其余规则条款
4. 蒸馏层结论（人类验证过）
5. 梗概层
6. 原文
7. 历史记忆与留痕摘要

低者与高者冲突时高者胜，**并在回复里说明"哪里冲突、按哪条走"**。记住一条线：*记住的历史永不低于当前的指令*。

## 4. 缓存与预算纪律

长会话的钱主要花在**前缀缓存**上：前缀命中要求逐字一致，中间改一个字，后面全失效。

- 稳定前缀（系统提示、规则文件、技能描述）**只在会话边界改**；不要在一个长会话中途改规则文件再继续干。
- 剪枝/压缩单次收益 **≥ 6,000 字符**才动手；小修小补的缓存损失可能大于省下的 token。
- 最近 4 条工具结果、钉住的关键约束，不剪不折。
- 失败教训只留一行（≤400 字符）；< 200 字符的输出不值得改写。
- 需要"省上下文"时优先**改变读取方式**（分片、按需、只要标识），而不是压缩已有内容。

## 5. 一条常用自检

动手前问三句：这条信息现在**还是真的**吗？还**用得上**吗？如果我删掉它会**立刻做错事**吗？第三个为"是"→ 它属于常驻层，不进按需分片。
