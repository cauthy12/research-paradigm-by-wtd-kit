# 20-logging · 留痕、digest、对账、索引

## 1. 什么时候必须留痕

- **必须**：多步任务、批量处理、跨会话任务、外部数据源任务、定时触发。
- **不必**：单轮问答、轻量解释、一次性小改。

判据：这件事**明天还能不能复述清楚**？不能 → 留痕。

## 2. 文件与格式

位置：`${runs_dir}/<任务名>.md`（文件名用任务名，不用时间戳做主键；同任务续写同一文件）。
只追加，不改写历史行；发现写错 → 追加一条更正行，说明"更正：第 N 行应为…"。

```markdown
# <任务名>

| 时间 | 状态 | 说明 |
|---|---|---|
| 2026-01-01 09:00 | 开始 | 目标：…；边界：… |
| 2026-01-01 09:40 | 进度 | 单元 1/3 完成：… |
| 2026-01-01 11:20 | 结束 | 结论：…；产出：<路径> |
| 2026-01-01 11:20 | 对账 | 源端 128 条 / 落盘 128 条，无差额 |
| 2026-01-01 11:20 | digest | 一句话结论 + 关键数字 |
```

- 表头固定三列（时间/状态/说明），脚本靠它判完整性。
- **开始行写不进去 = 立刻终止**，并说明"日志通道故障"。不要先干活后补日志。
- 失败与降级必须写进结束行：不得静默结束。

## 3. digest 与哈希

- 结束行必须有 `digest:`——一句话结论 + 一个可核对数字（条数、差额、金额、页码）。给未来的自己检索用。
- 哈希：**不做全链路哈希链**（并发追加必断，维护成本高于收益）。真需要防篡改时，只对单个文件的末行取 `sha256` 前 12 位写在 digest 里。

## 4. 外部源对账（结束行前必做）

凡从云端/网络拉取（网页、论文、研报、行情、妙记）：

- 对账三件套：源端条目数、源端时间戳、本地落盘数。
- 不一致就写差额与原因；无法核实写 `DEGRADED` + 未验证范围。
- "执行成功" ≠ "数据完整"。没有对账行的外部源任务视为未完成。

## 5. INDEX（脚本生成，勿手写）

- 每个留痕目录配一个 `INDEX.md`：文件 / 最后更新 / 行数 / 最新状态 / 摘要。
- 由脚本生成（如 `check.mjs --write-index`），**不手写、不注入上下文**。
- 文件多了之后，"靠文件名找任务"就不可靠了，索引是检索入口不是装饰。

## 6. 状态文件（活状态）

- 水位/计数/`known_issues`/待办这类状态文件是**活状态**，允许更新（与"正文只追加"不冲突）。
- 更新水位时以**单一事实源**为准，不要以 README 里的日期为准。
- 多平台共用状态文件时，指定一个平台为写者，其他平台只写 runs 并报告，避免并发写坏。
