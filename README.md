# research paradigm · by WTD

**给"一个人的研究公司"用的开工包。** 一条命令，在工作区铺开：规则分片、研究技能、目录骨架、体检脚本。

不是又一个行为闸插件。这个包里没有拦截、没有审批、没有中间件——只有**流程与判据**：该先查什么、什么时候停、什么算做完、结论靠什么站得住。

```bash
node init.mjs --dir ~/my-research-workspace --skills-scope project
```

零依赖，只要 Node ≥ 20。跑完你会得到一个能直接开工的工作区：

```
my-research-workspace/
├── AGENTS.md                 常驻约定（新会话自动读到，~2.5KB）
├── .research/
│   ├── config.yml            你的路径 / 禁区 / 额度归属 / 自有领域
│   ├── rules/                6 片按需规则（用到才读）
│   └── README.md             分片使用纪律
├── .agents/skills/           5 个研究技能（项目隔离）
├── tasks/  runs/  output/    三件套 / 留痕 / 交付
├── check.mjs                 体检：结构 + 留痕完整性
└── init.mjs
```

## 它是什么

一套**可执行的默认值**。把"研究"这件靠手感的事，拆成可以被下一次自己复用的六件事：

| 分片 | 回答的问题 |
|---|---|
| `00-core` | 哪些是硬边界？一条旧结论什么时候算作废？冲突时按谁？ |
| `10-retrieval` | 先查哪里？本地查不到怎么办？付费 API 谁能调？ |
| `20-logging` | 留痕写什么？外部数据怎么对账？索引谁生成？ |
| `30-failure` | 什么时候该停？出问题归哪一层？跨会话怎么接上？ |
| `40-delivery` | 文件怎么读？交付前查什么？落哪里？ |
| `50-governance` | 规则改在哪？平台差异写哪？定时任务归谁？ |

配套 5 个技能，任务命中时再加载：`rp-brief`（开题）、`rp-retrieval`（检索）、`rp-run-log`（留痕）、`rp-handoff`（交接）、`rp-deliverable-check`（交付校验）。

## 它不是什么

- **不是 agent 插件**：不注册工具、不注入 hook、不拦你的动作。任何能读 `AGENTS.md` 的 harness 都能用（DSH / Claude Code / 其他）。
- **不是知识库**：不替你存资料。它只规定"资料放哪、怎么检索、怎么标注来源强度"。
- **不是评测集**：不判断答案对不对。它只保证过程可复查。

## 三条设计原则

**1. 常驻的必须极少，其余的按需读。**
`AGENTS.md` 只放"不知道会立刻做错"的东西（硬边界、留痕三行、优先级）。其余分片进 `.research/rules/`，用到才读——因为每次会话付的是前缀钱，规则越长，每轮越贵，而且长到一定程度模型就开始遵守得不准。

**2. 参数出规则，规则里不留具体路径。**
`D:\工作`、某平台的归属、你的领域词，全部进 `config.yml`。规则正文保持抽象，这样换机器、换平台、给别人用都不用改规则。

**3. 作废靠墓碑，不靠删除。**
旧结论不是删掉，而是加一行 `superseded_by: <新条目> @日期 — 一句原因`。原文保留、可溯源，检索层默认不再采信。这样"知识库只追加"才不是一句口号，而是可机读的状态。

## 为什么不做成插件/preset

不是懒，是实测过三条硬约束：

| 约束 | 后果 |
|---|---|
| DSH 的 preset 声明**明确不提供目录/文件复制/删除** | 目录骨架、脚本、技能文件都铺不出来 |
| 预设内部的嵌套行**任何 patch 层都改不到**（`no patch layer can address by id`） | 想定制里面的 compaction、tool 组，只能整份重述 config |
| `cordis.patch.yml` **替换整份 config，不深合并** | 每加一个定制点，就要复制一整份列表并自己维护漂移 |

所以 v0.1 的形态是**纯文件包**：靠工作区 `AGENTS.md` 指令链 + `.agents/skills` 技能根 + 一个 Node 脚本。要动的是文件，不是运行时。
（将来如果要加"零副作用的一行命令"，再叠一个薄 preset 做外壳，不改变主体。）

## 体检

```bash
node check.mjs                 # 人读
node check.mjs --json          # 机器读
node check.mjs --write-index   # 重建 runs/INDEX.md
```

七类检查：目录与 6 片规则、`AGENTS.md` 是否含 rp-kit 段、5 个技能是否就位、`config.yml` 是否还有 `TODO`、最近 10 份留痕有无表头/结束行/digest、任务是否缺 `CONTEXT_INDEX.md`、`runs/INDEX.md` 是否过期。有 error 时退出码 1。

它只查**机械可验证**的部分。研究质量——判断对不对、证据够不够——脚本查不了，那部分靠 `rp-brief` 的判据和 `rp-deliverable-check` 的自检清单。

## 已知限制

- 规则是"默认值"，不是强制。模型仍可能跳过；`check.mjs` 只能事后看出缺痕。
- 不包含任何数据源接入（检索脚本、OCR、行情 API 都要你自己接，路径写进 `config.yml`）。
- 中文优先；英文场景需要自行调整分片措辞与技能描述。
- 没有测试套件跑真模型；`check.mjs` 只验证文件结构。
