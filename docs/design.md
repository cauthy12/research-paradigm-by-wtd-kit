# 设计说明：为什么是这个形态

这份文档记录 v0.1 的决策与依据，方便半年后自己（或别人）判断要不要推翻。

## 1. 需求

一个人做研究，痛点不在"缺工具"，而在这四件事：

1. **接不上**：隔一天回来，不记得做到哪、为什么这么定。
2. **重复花钱**：明明本地有资料，又去调了一次外部 API。
3. **说不清**：结论给了，但证据强度、口径、反面情形都没写。
4. **越用越乱**：规则、笔记、交付物混在一个目录，三个月后不敢动。

## 2. 备选形态

| 形态 | 优点 | 为什么不选（v0.1） |
|---|---|---|
| 行为闸插件 | 能强制拦截 | 拦截解决的是"做错动作"，这四件事是"没做动作"；而且插件把用户绑死在单一 harness |
| DSH preset 包 | 分发顺手、一行安装 | 见下节三条硬约束：铺不出目录，也改不动嵌套行 |
| 纯文件开工包 | 零依赖、任何 harness 可用、可读可改 | 无强制力，靠规则自觉 |
| 什么都不做，只写一篇方法论 | 成本最低 | 读过就忘，无法机械体检 |

结论：**纯文件开工包 + 体检脚本**。强制力交给"可见的缺口"（check 报 warn、留痕缺行），而不是中间件。

## 3. 三条硬约束（实测，来自 DSH 安装包）

1. `@deepseek-ai/dsh-agent-preset` 的 README 明确写：*声明不提供目录、文件复制或文件删除操作*。→ preset 不能铺目录骨架、不能装脚本与技能文件。
2. 预设内部的嵌套行无法被 patch 层按 id 定位（`whose nested rows no patch layer can address by id`）。→ 想改里面的 compaction / 工具组，只能整份重述。
3. `cordis.patch.yml` 的语义是"替换整份 config"，不是深合并。→ 每加一个定制点就复制一份列表，漂移自己维护。

补充一条不算约束但影响选择的事实：bundle 可以随包发 `skills/` 目录并挂载（`dsh-agent-preset` 自己就这么做），所以"发技能"可行；不可行的只有"铺工作区目录"。

## 4. 规则分片判据

一条规则放常驻层还是分片层，问一句：

> 如果模型**不知道**这条，会不会**立刻做错**，且代价高？

- 会 → 常驻（`AGENTS.md` 摘要 + `00-core.md` 全文）。例：禁区只读、只追加、密钥走环境变量、不编数据。
- 不会，但知道会做得更好 → 分片。例：检索顺序、归层表、交付校验清单、ADR 门槛。

分片的额外收益：每片可以独立演进、独立给别人用；常驻层保持小，前缀缓存稳定。

## 5. 优先级阶梯的来源

任何多源系统最后都要回答"冲突听谁的"。这条阶梯的顺序来自一个反直觉的经验：

**记住的历史，永不低于当前的指令。**

所以"用户当轮说了什么"最高，其次是硬边界（用户长期授权过、且违反代价不可逆的东西），再是其余条款，最后才是各种"记住的资料"。蒸馏层高于原文，是因为它经过人验证；原文高于留痕摘要，是因为摘要有损。

## 6. 墓碑机制

"只追加"如果只是不删文件，那条旧结论还是会被检索到、还是会被采信。所以墓碑必须是**机器可读**的：

```
superseded_by: <新条目> @2026-01-01 — 该数据被 2025 年报修订
```

检索层看到墓碑默认跳过；`check` 可以统计墓碑数量；人只需要扫墓碑行就知道知识在怎么演进。

## 7. 缓存纪律为什么写进规则

长会话里最大的隐性成本不是生成了多少 token，而是**前缀缓存失效**：中间改一个字，后面全部重付。所以：

- 稳定前缀（系统提示、规则文件、技能目录）只在会话边界改；
- 剪枝/压缩单次收益低于 6,000 字符就别动手，省的不够赔缓存；
- 省上下文优先改"读法"（分片、按需、只要标识），而不是压"已读的内容"。

这一条是从 DSH 生态里上下文类插件的实测参数（`minSavingsChars`、`protectRecentToolResults`、失败教训保留长度）归纳来的——但这里只取纪律，不取工具。

## 8. 什么情况下推翻这份设计

- DSH（或主流 harness）官方支持了"工作区脚手架"能力 → 目录铺设可以交给 harness，本包退化为纯规则集。
- 模型侧开始原生遵守超长规则（>10KB 也不衰减）→ 分片收益下降，可以合并。
- 出现稳定的"研究过程评测集" → `check.mjs` 可以从"结构检查"升级为"质量回归"。
